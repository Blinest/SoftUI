02能力矩阵：把「意图」变成「可信动作」

SEMANTIC

意图解析

大模型将自然语言解析为结构化策略：动作引用、触发条件、时序片段、异常中断。

MODEL

模型驱动

以 TDCRMOD1 模型包为唯一物理基准：曲率表、位姿表、形状表三位一体。

SOLVER

表驱动逆解

邻域加权反查，避免解析式模型在高曲率区的奇异与发散。

PLANNER

轨迹规划

末端路径离散化 + 曲率序列平滑，输出可执行的 κ 时间序列。

ENGINE

规则引擎

周期判定、张力阈值、跨阈值中断与自动恢复，支持时间线级联。

DISPATCH

确定性下发

以播放时钟为唯一时间基准，按时刻插值下发绝对位移，轨迹不可漂移。

TWIN

数字孪生

三维臂体与实机同源同帧，理论曲线与实际曲线并列对照。

GOVERN

安全治理

角色权限、使能校验、急停联动、失败归零四级防线。

AUDIT

可观测性

控制帧审计、执行日志、诊断包导出，全过程可回溯。

LAYER 1 · INTENT

03自然语言 → 策略语义

入口是「一句话」，出口是「可执行的数据结构」。中间不做黑盒猜测，而是把上下文一起交给模型，让生成结果天然对齐现场资产。

输入上下文（Context Injection）

  • 动作库清单（动作 ID / 名称 / 点位数 / 规划时长）
  • 模型库清单（型号 / 张力档位 / 曲率上限）
  • 现有方案与时序片段（增量编辑，而非从零生成）
  • 账号级 AI 凭证（每人独立 Key 与模型，互不干扰）

输出契约（Structured Output）

  • 方案（Scheme）：名称、规则集、时间线、中断表
  • 规则（Rule）：触发类型、阈值、目标动作 / 模型
  • 片段（Block）：执行动作 / 切换模型 / 等待 + 时长
  • 每个引用都必须命中现场真实 ID，杜绝“幻觉动作”

语义样例

“先切到 20N 模型，执行巡检动作 3 遍，中途张力超过 18N 就暂停 2 秒再继续”

↓ 编译为：switch-model → loop(3) → action → interrupt(tension > 18N, resume)

LAYER 1 · COMPILATION

04语义编译：从「意图」到「原语」

STEP 01

意图切分

识别任务主体、约束条件、异常策略三类要素。

STEP 02

实体对齐

把「巡检动作」对齐到动作库真实条目，把「20N」对齐到模型档位。

STEP 03

时序装配

按因果关系装配时间线，循环与等待转成可推进的片段。

STEP 04

约束求解

补齐时长、容差、安全检查项，输出通过校验的方案对象。

为什么不做「端到端直出」

  • 连续体机器人的安全边界必须显式表达，不能藏在黑盒权重里
  • 生成结果落盘为普通数据 → 可人工复核、可版本对比、可回滚
  • 编译产物与手写编排共用同一执行引擎，避免两条互不兼容的路径
LAYER 2 · MOTION LIBRARY

05动作库：示教、位姿与轨迹

动作的构成

  • 示教点序列：末端目标位置的三维路径，与当时臂体形态解耦
  • 坐标系约定：示教点存 three 系（毫米），求解前统一换轴到 svc 系
  • 容差：末端偏差允许上限，默认 2 mm，超差即判定不可行
  • 可行性缓存：按（模型 × 容差 × 点数）签名缓存，避免重复求解

多模型求解矩阵

同一个动作，对模型库中每个模型分别求解，产出独立的规划结果：

  • 可行 / 不可行 + 原因（不可达、超差、饱和）
  • 规划时长（由末端速度与轨迹长度决定）
  • 最大偏差（用于容差判定与质量分级）
  • 完整采样点（含曲率序列与末端坐标）—— 执行层直接复用

要点：动作不是录制的关节值，而是末端意图。同一动作在换臂、换模型后仍可复用。

LAYER 2 · SOLVER

06可行性求解：表驱动逆解

连续体机器人没有刚性关节，逆解不存在解析闭式。系统以 Cosserat 全阶模型离线打靶生成「位移 ↔ 形状」映射表，在线只做高效邻域反查。

模型包（TDCRMOD1）五段结构

  • KTB1：每样本 6 路张力 + 6 路位移增量（mm）
  • PTB1：四骨架点空间坐标（svc 系，米）
  • KSB1：弧长网格 61 节点
  • KKB1：61 节点曲率矢量（κx, κy）
  • META：样本数 / 张力上限 / 弯曲范围 / 曲率峰值

在线反查策略

  • 按末端位置检索最近邻组（K=10），距离倒数平方加权
  • 输出 6 路位移增量，同时给出最近邻距离用于「超域」判定
  • 距离超过阈值 → 判定目标越界，拒绝下发并提示回撤
  • 全流程只读常量表，实时性由表驱动保证，而非迭代求解
工程价值：把「每帧几百毫秒的迭代求解」压缩为「一次内存邻域检索」，实时链路才能成立。
LAYER 2 · PLANNER

07规划采样与曲率平滑

  1. 路径离散化：末端示教点按等弧长重采样，形成密集目标点列。
  2. 逐点反查：每个目标点调用表驱动逆解，得到该时刻的 6 路段曲率。
  3. 序列平滑：对 κx / κy 分别做滑动平滑 —— 分量分别处理，方向角才不会翻转。
  4. 回算校验：用平滑后的曲率积分回末端位置，与目标比对，统计最大偏差。
  5. 可行性裁决：任一采样点不可达、或最大偏差超容差，则判该模型不可行并给出原因。

为什么必须平滑

最近邻反查在小邻域切换时会产生微跳变；直接下发会让电机反复加减速，表现为顿挫与异响。

为什么分量分离

对 κ 的模与角分别平滑会在过零点引入反向旋转；对 κx/κy 做分量平滑可保持方向连续。

LAYER 3 · POLICY

08策略方案：三层数据结构

LAYER A

规则集 Rules

周期型规则（每 N 秒触发）与张力型规则（跨阈值触发）；命中后执行动作或切换模型。

LAYER B

时间线 Timeline

有序片段队列：执行动作 / 切换模型 / 等待；每段独立时长，整体串行推进。

LAYER C

中断表 Interrupts

运行期异常处理：张力跨阈值时暂停、执行补偿动作、再恢复原时间线。

方案的生命周期

  • 本地草稿 → 编辑态，不与现场冲突
  • 提交审批 → 操作员改动进入待审队列，不直接影响生产
  • 直传生效 → 管理员改动立即同步，全部终端 5 秒内一致
  • 标记删除 → 已生效方案先摘除再落盘，避免历史终端残留
LAYER 3 · ENGINE

09规则引擎与中断编排

节拍式判定

  • 引擎以稳定节拍轮询：读取规则、读取实时张力、必要时推进时间线
  • 周期规则用「上次触发标记」去重，避免同一窗口重复命中
  • 张力规则维护滑动历史窗口，抑制瞬时噪声误触发

中断与恢复

  • 跨阈值 → 记录中断事件 → 暂停当前播放 → 执行补偿片段
  • 补偿完成后按原进度恢复，时间线状态不丢失
  • 无恢复策略时停留在安全姿态，等待人工介入

执行仲裁

同一时刻只允许一条执行主线：手动播放与策略时间线互斥，后发起者接管，被接管者必须完整收尾 —— 否则会出现「界面显示在播、实际已停」的状态撕裂。

LAYER 4 · DISPATCH

11播放时钟驱动的位移下发

下发不是“跟着渲染帧走”，而是“跟着时间轴走”：以播放时钟为唯一基准，按时刻在位移序列上插值，输出绝对位移帧。

为什么要用播放时钟

  • 渲染帧率会抖动，用帧号推进会让轨迹随时间漂移
  • 暂停 / 恢复天然正确：时钟停，下发停，不需额外状态
  • 拍与拍之间的缺口由插值补齐 —— 不丢帧、不改轨迹

下发帧的三重约束

  • 绝对量：每帧给出六路电机的目标位移，后帧自然覆盖前帧
  • 节拍化：固定节拍发送，避免把串口打满
  • 终点钉住：结束补发终点帧，确保停在规划终点而非半途

链路时序

规划表 → 位移序列 → 播放时钟 → 时刻插值 → 多电机同步帧（0x04）→ 驱动器 → 实测位置回读 → 曲线与监控

LAYER 4 · DIGITAL TWIN

12数字孪生与三维同步

两跳注入架构

  • 播放每帧把曲率分布写入共享注入槽（两跳直达渲染循环）
  • 避开「回调 → 状态 → 派生 → 属性 → 引用 → 渲染」的长链路
  • 长链路上任一跳断裂，表现都是“界面在播、臂体不动”，极难定位

形位平滑

  • 目标形位与实测形位各自独立阻尼，互不干扰
  • 目标清空时平滑回落至实测，而非瞬跳
  • 视角状态持久化：切页签返回后相机、勾选、轨迹全部还原

理论 vs 实际

曲率分布、腱张力、形变投影三条曲线并列：实线为实测/快照，点线为由指令反推的理论值 —— 偏差即模型与执行质量的度量。

LAYER 5 · SAFETY

13安全边界与权限治理

GATE 01

角色权限

动作下发需 SendMotionCommand 能力位；操作员与管理员的审批路径分离，越权直接拒绝。

GATE 02

使能校验

未使能或处于急停状态时，任何下发链路一律短路，界面给出明确原因而非静默失败。

GATE 03

可及性判定

目标超出位移表覆盖范围即拒绝执行，提示回撤，不尝试“近似硬发”。

GATE 04

异常收敛

连续下发失败达阈值即自动停止跟随；失败归零策略确保异常后回到确定姿态。

审批与人机边界

  • 改动分「直传」与「待审」两条通道，由角色决定，不由客户端声明
  • 空改动不产生审批单 —— 无信息量的流程噪音同样是缺陷
  • 现场急停永远优先于软件层任何编排逻辑
LAYER 5 · OBSERVABILITY

14可观测性与审计

TRACE

控制帧审计

EXPORT

模型包、动作轨迹、方案数据标准化导出，支持迁移与归档。

CONCLUSION

16工程结论

确定性优先

时间轴是唯一时间基准。任何“按帧推进”的写法都会在掉帧、切页、后台节流时引入漂移。

模型即契约

模型包是物理事实的唯一来源。前端不做解析式近似，避免“能加载、形状却错”的隐性错误。

状态单一来源

执行态、显示态、播放态必须同源。多份状态是“界面在播、电机已停”这类问题的根因。

异常即收敛

失败不沉默：要么归零、要么停跟随、要么显式报错。静默失败在现场等于事故。

演进方向

  • 轨迹表加密采样，进一步压低邻域切换带来的微跳变
  • 下发电机引入实测位置闭环与速率整形，兼顾跟随精度与运行平顺
  • 规则引擎扩展为可视化编排：策略即图，图即策略
