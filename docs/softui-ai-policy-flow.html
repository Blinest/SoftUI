智能策略编排 · 逻辑流程

AiComposeDialog.compose → RPC ai_compose_policy → 校验 → 草案 → 方案入库
前端主流程 后端（Rust） 判定点 失败分支（不落地） 入库与审批
01

用户输入 compose()

自然语言需求，例如「先切 20N 模型，巡检动作跑三遍，张力超 18N 停 2 秒再继续」。

  • 拼接对话历史：之前的对话：…\n\n本次要求：…
  • 用户气泡即刻上屏；setDraft(null) 清空上一轮草案
02

组装上下文 context

把「现场有哪些东西」一并交给模型，避免它编造不存在的对象。

  • models[]：仅 { id, name } —— 物理参数（臂长 / 曲率上限）不进来，由动作库的可行性检查负责
  • actions[]：{ id, name, durationSec }，时长取自可行性缓存的 feasibility.models[].durationMs / plan.durationMs，未检查过为 null
  • currentScheme：对话框自身的 draft（AI 上一轮产物，无则 null），不是正在编辑的方案
  • 序列化后以「可用清单：{JSON}」并入 user message；同一份清单也用于前端 problems[] 校验
03

RPC：ai_compose_policy lib.rs

KEY账号自有 Key 优先 → 回落全局配置 → 都没有则报错
SYSAI_POLICY_SYSTEM_PROMPT：输出骨架 + 5 条规则（只能用 context 里的 id、kind 枚举、时长范围…）
USR可用清单：{context}\n\n用户需求：{prompt}
REQresponse_format: json_object · temperature: 0.2 · 超时 60s
POSTOpenAI 兼容 /chat/completions，Bearer 鉴权
TAKE取 choices[0].message.content
CLEAN剥 ```json 围栏 → serde_json::from_str
F1 · HTTP / 解析失败 非 2xx → 截断前 300 字报错
content 缺失 → 「响应里没有 content」
JSON 非法 → 「返回的不是合法 JSON」
04

逐条语义校验 problems[]

  • action → actionId 必须命中 context.actions
  • switch-model → modelId 必须命中 context.models
  • durationSec ∈ (0, 3600]
  • 中断 targetId → 按 targetKind 命中 models / actions
F2 · 校验不通过 最多回显 4 条问题，整个方案不落地；用户改口后带历史重走 01
05

生成草案 setDraft()

主键由系统生成，不采信模型给的 ID。

  • 时间线：id = block-{Date.now()}-{i}
  • 中断：id = intr-{Date.now()}-{i}，补 enabled=true / trigger="tension-spike" / resume=true / note=""
  • 气泡摘要：N 段时间线 · M 条中断
F3 · 用户不接受 「再短一点」「阈值改成 3N」→ 作为新输入回到 01，currentScheme 与历史一起带给模型
06

写入方案 · 按角色分流 persist()

管理员canWriteDirectly() → 直接落盘生效，全部终端 5 秒内同步
操作员submitUiStore() → 进入待审队列，批准后才生效
