远程控制 · 一主多从中继架构

Web Serial 只能在打开的浏览器里用 → 天然主从；其余端靠后端中继

核心前提：串口句柄属于打开它的那个浏览器。所以系统里只有一台「主端」能真正读写串口， 其余端（手机 / 另一台电脑）通过后端中继命令与数据。三条通道各自独立：命令下行、数据上行、UI 同步。

从端 REMOTE

手机 / 另一台电脑，没有串口句柄。

  • isLocal() === false
  • 命令必须经后端中继
  • 画面靠拉取后端缓冲

后端 NODE + RUST

三条通道的中枢，全部是无状态转发：

  • 命令队列：tx buffer 按端口排队
  • 实时环：live_ring 保留 240 帧
  • 单槽广播：ui_publish / ui_wait
  • 审计：control_frame_log、会话录制

主端 MASTER · 持串口

插着设备的那台电脑，浏览器持有 SerialPort。

  • 本地解析：字节不出浏览器
  • 本地查表：vc_table_index 190KB
  • 直发：0x11 帧直接写串口（ms 级）
  • isLocal() === true

串口 → 下位机 DEVICE

115200，V2 帧（0x55）。上行状态帧 5Hz，六电机 + 六张力通道。

命令下行（从端 → 主端 → 串口） 数据上行（串口 → 主端 → 后端 → 从端） UI 同步（双向单槽广播）

① 命令下行

从端点按钮 → 后端编码成帧 → 压进该端口的 tx 队列 → 主端长轮询取走 → 写串口。主端自己不走这条路：本地查表算完位移直接写串口。

② 数据上行

主端读字节并在浏览器内解析 → 环形缓冲 → 1Hz 上报后端留档 → 从端拉窗口渲染。主端自己用本地缓冲，零往返。

③ UI 同步

拖动目标、末端位姿、目标位移、引擎开关都写进单槽 → ui_wait 有更新立即返回。应用远端值时不回发，避免回环。

时序举例 · 手机拖动

  1. 手机拖手柄 → 本地算目标分布
  2. ui_publish("drag", 分布) → 电脑端 3D 立即跟着动
  3. 若开「实时跟随」→ 走命令下行 → 主端拉取 → 写串口
  4. 主端串口数据 → 本地解析 → 1Hz 上报 → 手机拉窗口 → 曲线更新

瓶颈与演进

  1. 从端指令中继延迟 ≥300ms（长轮询超时）
  2. 多条 HTTP 轮询抢连接池 → 偶发排队十几秒
  3. 根治：三条轮询合并成一条 WebSocket
  4. 下行 push（<10ms）、上行广播（≪100ms）、UI 同连接
